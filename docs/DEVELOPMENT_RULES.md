# 开发规则

每次开发先阅读 REQUIREMENTS、ISSUES、CHANGELOG 和本文件。用户当前明确需求优先。

## 长期强制准则

1. GitHub 仓库和版本下载包不得包含业务数据。Mac/Windows 从本机工具目录启动时，如果同级存在 `data/`，使用它作为便携数据；否则使用该电脑的本机持久数据目录。Mac 从 NAS 启动始终使用 Mac 本机数据目录，不从 NAS 读写业务数据。SQLite 只允许单台电脑串行访问。
2. 禁止 watcher、自动同步、NAS 冲突检测及 `SYNC_CONFLICT`。电脑间数据只允许用户关闭程序后手动复制完整 `data/`；同一份数据不得同时在多台电脑使用。
3. 只有正式启动器可设置 `POINT_QUOTE_USER_DATA_DIR`。便携数据目录可由用户在版本目录间手动搬运；程序不得清理、镜像或覆盖它。新版本下载包不包含业务数据；迁移先备份并核对。
4. 收集一组需求后统一开发、测试和发布，不因每个小修复升级正式版本。开发版本用 `<版本>-dev`，功能完成待验收用 `<版本>-beta`，验收通过后使用稳定版本号。
5. 每次版本更新开始前，先备份上一版程序到工具目录同级的 `版本备份/智能图纸点位与报价工具 v<上一版>`；代码备份不含业务数据，且不得覆盖已有目录。业务数据另行备份到独立路径；检查两份备份后才开始修改或迁移。
6. GitHub Release ZIP 解压后的目录名统一为 `态元智控工具V<版本号>`。使用便携数据更新版本时，将完整 `data/` 复制到新版本工具目录。
7. 版本完成同步更新 VERSION、CHANGELOG、REQUIREMENTS、ISSUES 和帮助/版本记录，写明新增、优化、修复、结构变化、兼容性与测试结果。
8. 按版本内约定顺序实施最小修改，不增加范围外功能，不更换技术栈或引入新数据库。
9. MouseMove 只更新内存和画面，不写文件、不保存报价、不扫描产品库、不重读数据；MouseUp 后才提交。
10. 产品适用类型可以多于图纸布点类型，不能由新增产品分类自动生成工具栏图标或快捷键。
11. 自动化、Mac 和 Windows 实机结果分别记录，不得把模拟测试当作实机通过，不提前标记 Stable。
12. 对用户只提供 `start-mac.command` 与 `start-windows.bat` 两个正式启动入口；平台内部 API、网页服务和校验脚本可作为依赖保留，不新增 LAN/local/Portable 平行入口，除非用户明确提出。
