## v3.4-dev GitHub 程序与本机数据分离（RQ-020）

状态：🟡 开发中。用户授权将不含业务数据的程序公开发布，供用户下载；支持电脑间手动转移完整 `data/`，不提供自动同步。

- Git 仓库和下载包排除完整 `data/`、客户资料、产品库、图纸、附件、数据库、备份、导出和运行日志。
- Mac/Windows 从本机工具目录启动时，如果同级有 `data/` 就使用便携数据；否则 Mac 使用 `~/Library/Application Support/TaiyuanPointQuote/data/`、Windows 使用 `%LOCALAPPDATA%\TaiyuanPointQuote\data\`。Mac 从 NAS 启动始终使用 Mac 本机数据，不读写 NAS 上的 `data/`。
- 本机回退目录不存在时，首次启动可把旧工具目录 `data/` 复制到本机数据目录；原目录保留。便携模式直接读取工具目录旁的 `data/`。
- 程序不得清理或镜像覆盖任何业务数据；版本下载包不包含业务数据。便携数据升级时由用户手动复制到新版本目录。
- 电脑间只允许关闭程序后手动复制完整 `data/`；不做后台同步，同一份 SQLite 数据不得在多台电脑同时打开。
- GitHub Release ZIP 解压后的目录名为 `态元智控工具V<版本号>`，由 Release 打包工作流生成；GitHub Code → Download ZIP 不支持自定义解压根目录名。
- 首次上传使用 `3.4-dev` 标记；完成 Mac/Windows 实机回归并经用户验收前，不标记为稳定版。

验收：干净版本 ZIP 不含 `data/`，解压根目录使用 `态元智控工具V<版本号>`；本机工具目录有便携 `data/` 时 Mac/Windows 能使用它，缺少时能回退到 OS 本机目录；Mac 从 NAS 启动不读写 NAS 数据；手动跨机复制完整 `data/` 后数据可用；GitHub 公开仓库只包含工具程序。

## RQ-003B 区域与点位点击优先级

状态：🟢 已解决（2026-09-30 用户原项目实机复验通过）

- 设备点位优先于调光/非智能区域。
- 区域内部有点位时选点位，点击空白才选区域。
- 必须统一覆盖选择、拖动、删除、右键和属性编辑。

验收：单区域、重叠区域、不同缩放下均无选择冲突。

### RQ-017-HE 点位即时反馈与页面读取耗时

状态：🟡 实现已开始，运行环境性能实测及 Windows/NAS 验收未完成；RQ-017-H 保持 🔴。

- 点位创建先在编辑器状态中插入临时点位并请求下一帧绘制，再提交新增点位 API；失败时移除临时点位并提示，不等待知识库写入或读取完整项目。
- 点位产品校验与报价产品映射使用已加载的进程内 ID 映射；产品目录索引有效期 30 秒，过期时先用缓存响应并在后台刷新，避免产品列表/报价等待 SMB 递归扫描。
- 点位、项目资料和报价的数据库型修改在 SQLite 本地提交成功后，按项目合并并延迟 750ms 写入知识库；同项目短时间连续变更会取消旧任务，仅保留最新一次同步。现有同文件串行写入保护继续有效。数量/大小/颜色/角度等点位属性先乐观更新 UI，再经 800ms 合并保存。

## 开发纪律

一次只处理一个 RQ 阶段；开发前阅读本文件、`ISSUES.md`、`CHANGELOG.md` 和 `DEVELOPMENT_RULES.md`，完成后同步更新。未完成验收不得标记为“已解决”，发现新问题必须新增 ISSUE。

所有长期业务数据原则上必须以态元智控知识库作为最终持久化来源。内部数据库、JSON、localStorage 或其他存储只能作为缓存、索引或运行状态。新增功能必须先明确知识库写入、重新读取、迁移和恢复方案。
