## 2026-09-30｜RQ-017-HA Windows 性能与同步诊断

### 接入与编号

- 读取《智能图纸点位与报价工具-RQ015-Windows性能与同步稳定性专项.md》。因项目已有 RQ-015 macOS 启动入口，新专项顺延为 RQ-017-H，原文阶段 A～D 保持不变。

### 诊断结论

- Windows 当前仍把 SQLite 数据目录放在 NAS 工具目录，是文件锁、I/O 延迟和同步失败的首要架构风险。
- 项目/品牌读取与所有写请求触发全库同步；写请求前后各一轮。产品读取与查找使用递归 Markdown 扫描。
- 点位详情若逐字符修改会直接 PATCH；服务费面板初始化会产生未修改数据的请求。点位拖动不是鼠标移动逐帧写入，报价主要编辑已有 700ms 防抖。
- 当前没有 watcher，排除 watcher 自触发循环。
- 旧代码没有请求编号和结构化堆栈，因此无法对历史某一次 500 给出唯一异常；已确认会直接导致 500 的具体路径包括 SMB/权限/文件占用、原子替换失败及 SQLite 锁或 I/O 错误。

### 本次修改

- 新增 `backend/diagnostics.py`：本机 JSONL 日志、requestId 上下文、错误分类、完整堆栈和日志轮换。
- `backend/app.py`：API 中间件统一追踪请求；异常返回 requestId 和错误分类；新增诊断状态接口。
- `backend/knowledge_repository.py`、`backend/product_repository.py`：记录全量扫描文件数、扫描/写入耗时和文件路径。
- `run-windows-api.bat`、`macos-launcher/run-macos.zsh.txt`：诊断日志明确写入本机目录，不增加 SMB I/O。
- 三个前端 API 包装器显示错误编号，便于用户截图反馈。
- `backend/test_app.py`：增加 RQ-017-HA requestId、文件锁分类、日志堆栈和扫描指标测试。

### 验证与基线

- 前端生产构建通过，1585 个模块完成转换。
- 后端完整回归 `26 passed`；文件占用模拟正确返回 `FILE_LOCKED` 与 requestId。

## 2026-09-30｜ISSUE-021 复用运行中的服务时不再使用旧程序

### 问题

改完前端再打开工具，界面仍是旧的。用户实际遇到过：帮助页使用手册已经写进代码，重新打开应用却看不到变化。

### 原因

`macos-launcher/run-macos.zsh.txt` 开头只要检测到 5173 与 8000 都在响应，就直接打开浏览器并退出，**跳过了 `rsync` 镜像步骤**。而实际运行的前端是共享盘程序在本机的镜像副本（`~/Library/Caches/TaiyuanPointQuote/frontend`），镜像不刷新，看到的自然是旧代码。开发时手工跑一次 rsync 可以绕过，但正常使用路径会一直踩到。

### 修改文件

- `macos-launcher/run-macos.zsh.txt`：把 `sync_frontend()` 提前定义，新增 `frontend_needs_sync()`（用 `rsync -an -i` 预演判断共享盘程序是否比本机缓存新）；复用分支在打开浏览器前先补一次同步。Windows 启动器未修改，原因见下。

### 解决方案

- 复用运行中的服务时，先做一次 `rsync -an -i` 预演；有输出即代表共享盘程序更新，此时同步镜像后再打开浏览器，vite 会自行热更新已打开的页面。
- 镜像已是最新时预演无输出，保持原有的「秒开复用」行为，不引入额外等待。
- 不再重复书写排除规则，`node_modules`、`dist`、`*.tsbuildinfo` 的排除集中在一处（`frontend_needs_sync` 与 `sync_frontend` 共用同一套参数）。
- 同步失败不阻断打开（`|| true`），行为与之前一致，只多一行提示。

### 关于 Windows

`start-windows.bat` **不需要修改**，它本来就不会踩这个坑：

1. 第 35～41 行先调用 `stop-windows-runtime.ps1` 强制释放 8000/5173 端口，旧服务一定被关闭；
2. 第 79～85 行再执行 `robocopy /MIR` 从共享盘全量镜像前端；
3. 第 93～104 行按 `package-lock` 哈希决定是否 `npm ci`；
4. 最后才重启两个服务并打开浏览器。

即每次启动都是「先杀进程 → 再全量镜像 → 再重启」，不存在复用旧程序的路径。`start-windows-lan.bat` 只是转调 `start-windows.bat lan`，同一套流程。

- 实测复用分支：人为制造一处镜像差异后运行启动器，输出「检测到前端程序有更新，正在同步到本机运行缓存...」并完成同步；再次运行无输出、直接复用。两次运行后 5173 与 8000 均正常响应。
